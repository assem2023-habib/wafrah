# وثيقة التقنيات — تطبيق وِفرة

> هذه الوثيقة مستقلة عن وثيقة التصميم ووثيقة منطق العمل. تتناول فقط الأدوات والمكتبات والهيكلة التقنية.

---

## 1. الإطار الأساسي

- **Flutter** (أحدث إصدار مستقر) — تطبيق موبايل واحد لنظامي Android و iOS من قاعدة كود واحدة.
- دعم **RTL** والعربية بشكل كامل عبر `flutter_localizations`.

---

## 2. إدارة الحالة والتنقل: GetX

- `get` (GetX) يُستخدم لثلاث مهام في آن واحد، وهذا مناسب لحجم التطبيق البسيط:
  1. **إدارة الحالة (State Management)** عبر `GetxController` و `Obx` / `GetBuilder`.
  2. **التنقل بين الشاشات (Routing)** عبر `Get.to()` / `Get.off()` بدون الحاجة لـ `Navigator` و `context` في كل مكان.
  3. **حقن الاعتماديات (Dependency Injection)** عبر `Get.put()` / `Get.lazyPut()` لتمرير خدمات التخزين للـ Controllers.

**سبب الاختيار:** يقلل الكود المتكرر (Boilerplate) مقارنة بـ Provider/Riverpod، ومناسب لتطبيق بمستخدم واحد ومنطق بسيط نسبيًا.

---

## 3. التخزين المحلي: Hive

- `hive` + `hive_flutter` — قاعدة بيانات محلية بدون SQL، تخزّن الكائنات مباشرة (Key-Value / Objects)، سريعة جدًا ومناسبة لحجم بيانات مستخدم واحد.
- كل موديل بيانات (Category, Product, Transaction, ElectricityReading, ElectricitySettings) يحصل على **Hive TypeAdapter** خاص به (يُولَّد تلقائيًا عبر `hive_generator` + `build_runner`).
- **Boxes مقترحة:**
  - `categoriesBox`
  - `productsBox`
  - `transactionsBox`
  - `electricityReadingsBox`
  - `settingsBox` (يحتوي: التعرفة، الوضع الليلي/النهاري، إعدادات أخرى)
- التهيئة تتم مرة واحدة عند بدء التطبيق (`Hive.initFlutter()`) قبل عرض أي شاشة، أثناء شاشة التحميل (Splash).

---

## 4. الرسوم البيانية: fl_chart

- `fl_chart` لعرض:
  - رسم دائري (Pie Chart) لتوزيع المصاريف حسب الصنف.
  - رسم عمودي (Bar Chart) للمقارنة بين الدخل والمصروف (يومي/أسبوعي/شهري).
- تخصيص الألوان مباشرة من لوحة ألوان التطبيق (وليس الألوان الافتراضية للمكتبة) — راجع وثيقة التصميم.

---

## 5. مكتبات مساعدة

| المكتبة | الغرض |
|---|---|
| `intl` | تنسيق الأرقام (فواصل الآلاف) والتواريخ بالعربية |
| `path_provider` | تحديد مسار التخزين المحلي المطلوب لـ Hive |
| `flutter_localizations` | دعم RTL والعربية في عناصر Flutter الجاهزة (مثل DatePicker) |
| `google_fonts` أو خط مضمّن يدويًا | لتحميل خط Cairo/Tajawal المذكور في وثيقة التصميم |

---

## 6. هيكلة المجلدات المقترحة (نمط GetX)

```
lib/
 ├─ main.dart
 ├─ app/
 │   ├─ data/
 │   │   ├─ models/          (Category, Product, Transaction, ElectricityReading, Settings)
 │   │   └─ services/        (HiveService لكل موديل: add/update/delete/getAll)
 │   ├─ modules/
 │   │   ├─ home/            (controller + view)
 │   │   ├─ add_expense/
 │   │   ├─ add_income/
 │   │   ├─ transactions/
 │   │   ├─ categories/
 │   │   ├─ products/
 │   │   ├─ statistics/
 │   │   ├─ electricity/
 │   │   └─ settings/
 │   ├─ routes/              (app_pages.dart, app_routes.dart)
 │   ├─ theme/                (app_colors.dart, app_theme.dart - light/dark)
 │   └─ widgets/              (بطاقات، أزرار، حقول مشتركة)
 └─ splash/
```

- كل Module يحتوي `Controller` (GetxController) + `View` (Widget) بشكل منفصل ومستقل، بحيث تعديل منطق شاشة لا يؤثر على شاشة أخرى.
- طبقة `services` هي الوحيدة التي تتحدث مباشرة مع Hive — الـ Controllers لا تتعامل مع Hive مباشرة، بل عبر الخدمات، لتسهيل أي تعديل مستقبلي على طريقة التخزين دون المساس بمنطق الشاشات.

---

## 7. ملاحظات عامة

- لا حاجة لأي Backend أو API — التطبيق يعمل بالكامل دون اتصال إنترنت (Offline-first) بما أنه لمستخدم واحد وتخزين محلي بالكامل.
- لا حاجة لنظام تسجيل دخول/حسابات.
