# الشاشة 11: إضافة قراءة كهرباء (Add Reading)

> **المسار:** `/add-reading` · **الملفات:** `lib/modules/add_reading/*`

## الغرض

تسجيل قراءة العدّاد التراكمية بأقل مجهود، مع معاينة فورية للاستهلاك وتكلفته قبل الحفظ.

## ترتيب الحقول (DOCS 01 §5.10)

1. **بطاقة القراءة السابقة** (من المرجع): قيمتها بالك.و وتاريخها — مرجع بصري يسهّل إدخال القيمة الجديدة.
2. **القراءة الجديدة** — `AppNumberField` بوحدة «ك.و» ثابتة، لوحة رقمية مباشرة.
3. **بطاقة معاينة حية** (تظهر عند إدخال قيمة > 0 ووجود قراءة سابقة): الاستهلاك (فرق العدادين) + التكلفة التقريبية من شرائح التعرفة.
4. **من تاريخ** — `AppDateField` **إجباري**، افتراضياً اليوم، بلا قيد على الماضي.
5. **إلى تاريخ** — `AppDateField` **اختياري** بتسمية «(اختياري)»، ومعه زر نصي «بدون تاريخ نهاية» لتعطيله بوضوح إن حُدد ثم ندم.
6. **ملاحظة** اختيارية.

زر «حفظ القراءة» مثبت أسفل الشاشة بلون `primary`، ويُعطل أثناء الحفظ.

## التحقق

| الحالة | الرسالة وموضعها |
|---|---|
| قيمة ≤ صفر | inline تحت الحقل: «القيمة يجب أن تكون أكبر من صفر» |
| تاريخ النهاية قبل/مساوٍ للبداية | بانر أعلى النموذج: «تاريخ النهاية يجب أن يكون بعد تاريخ البداية» |
| نجاح | علامة صح scale-in + «تم تسجيل القراءة!» + رجوع تلقائي بعد 1200ms |

## الحالات الأربع (DOCS 07 §10)

- **عادية:** نموذج جاهز (+ بطاقة سابقة إن وجدت).
- **فارغة:** لا حالة فراغ خاصة؛ التحقق هنا يتعلق بالتواريخ لا الأصناف.
- **تحميل:** مؤشر لحظي أثناء قراءة آخر قراءة والتعرفة.
- **خطأ:** كما في جدول التحقق أعلاه.

## المنطق المرتبط

- الحفظ ينشئ `ElectricityReading(fromDate, toDate?, kwhValue, note?)`.
- المعاينة والحسابات عبر `TariffCalculator` المشترك — نفس مصدر حقيقة شاشتي الرئيسية والسجل.

## التنقل

- يُفتح من زر «قراءة جديدة» في الرئيسية الكهربائية · بعد الحفظ يعود لها وهي محدثة تلقائياً.
