# الشاشة 3: إضافة مصروف (Add Expense)

> **المسار:** `/add-expense` · **الملفات:** `lib/modules/add_expense/*` · **تعمل أيضاً كوضع تعديل** عند تمرير `id` حركة

## الغرض

تسجيل مصروف في ≤3 خطوات ظاهرة، أو تعديل مصروف قائم — بنفس الشاشة.

## ترتيب الحقول (عمودي، DOCS 01 §5.2)

1. **الصنف** — `AppDropdownField` بقائمة سفلية منسدلة؛ يعرض أصناف نوعها «مصروف» أو «كلاهما».
2. **المنتج** — يظهر **فقط** بعد اختيار صنف له منتجات، وقائمته محصورة بمنتجات ذلك الصنف. لا صنف/لا منتجات = الحقل مخفي كلياً.
3. **المبلغ** — `AppNumberField` بارتفاع 52 ونص 20px ولوحة أرقام مباشرة، تنسيق فواصل آلاف وأرقام عربية أثناء الكتابة، وحدة «ل.س» ثابتة لا تُحذف.
4. **التاريخ** — `AppDateField` يفتح الروزنامة المخصصة بألوان التطبيق؛ افتراضياً اليوم، بلا قيد على الماضي.
5. **ملاحظة (اختياري)** — حقل نصي بتلميح «أضف ملاحظة...».

زر الحفظ مثبت أسفل الشاشة بلون `secondary` («حفظ المصروف» / في التعديل: «تحديث المصروف»).

## بطاقة القراءة السابقة والمعاينة

- عند فتح وضع التعديل تُعبأ كل الحقول تلقائياً من الحركة المستدعاة.

## الحالات الأربع (DOCS 07 §2)

- **عادية:** النموذج جاهز.
- **فارغة:** لا أصناف معرفة إطلاقاً → حالة فارغة «لا توجد أصناف / أضف صنفًا أولًا من إدارة الأصناف» وزر ينقل مباشرة لإدارة الأصناف بدل عرض قائمة فارغة.
- **تحميل:** مؤشر أثناء جلب الأصناف.
- **خطأ:** خطأ القيمة inline تحت الحقل («القيمة يجب أن تكون أكبر من صفر»)، وباقي الأخطاء بانر أعلى النموذج لا يختفي إلا بإغلاقه أو تصحيح السبب. زر الحفظ يُعطل أثناء الحفظ لمنع التكرار.

## المنطق المرتبط

- رفض القيم ≤ صفر (`Validators.positiveNumber` يقبل الأرقام العربية وفواصل الآلاف).
- حفظ عبر `ITransactionRepository.add/update` مع `type: expense`.
- عند نجاح الحفظ: علامة صح scale-in ~350ms + «تم الحفظ بنجاح!» ثم رجوع تلقائي بعد 1200ms.

## التنقل

- رجوع بالهيدر · بعد الحفظ عودة للشاشة السابقة (الرئيسية/تفاصيل الحركة).
