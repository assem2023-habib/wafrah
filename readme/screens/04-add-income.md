# الشاشة 4: إضافة دخل (Add Income)

> **المسار:** `/add-income` · **الملفات:** `lib/modules/add_income/*` · **تعمل أيضاً كوضع تعديل** عند تمرير `id` حركة

## الغرض

تسجيل دخل بأسهل مسار ممكن — الدخل لا يتطلب صنفاً ولا منتجاً (وثيقة المنطق §2: `categoryId` غير مستخدم للدخل).

## ترتيب الحقول (DOCS 01 §5.3)

1. **المبلغ** — نفس `AppNumberField` بشاشة المصروف (لوحة رقمية، فواصل حية، أرقام عربية، «ل.س» ملحقة).
2. **التاريخ** — `AppDateField` بالروزنامة المخصصة، افتراضياً اليوم.
3. **ملاحظة/شرح الدخل (اختياري)**.

زر الحفظ مثبت أسفل الشاشة بلون `primary` («حفظ الدخل» / في التعديل «تحديث الدخل») — تمييز بصري عن شاشة المصروف ذات اللون الثانوي، مطابق للمرجع.

## الحالات الأربع

- **عادية:** نموذج فارغ جاهز.
- **فارغة:** لا حالة فراغ خاصة — الدخل لا يحتاج أصنافاً (DOCS 07 §3).
- **تحميل:** لحظي عند وضع التعديل فقط.
- **خطأ:** خطأ القيمة inline تحت الحقل؛ أي خطأ آخر بانر أعلى النموذج. زر الحفظ معطل أثناء الحفظ.

## المنطق المرتبط

- رفض القيمة ≤ صفر بنفس رسالة التحقق الموحدة.
- حفظ `Transaction(type: income)` بدون categoryId/productId.
- وضع التعديل: قراءة `arguments` (معرف الحركة)، تعبئة الحقول، ثم `update` بدل `add` مع تبديل العنوان إلى «تعديل الدخل».
- النجاح: علامة صح + «تم الحفظ بنجاح!» + رجوع تلقائي بعد 1200ms.

## التنقل

- يُفتح من زر SpeedDial «دخل» في الرئيسية أو من «تعديل المعاملة» في تفاصيل الحركة الدخل.
